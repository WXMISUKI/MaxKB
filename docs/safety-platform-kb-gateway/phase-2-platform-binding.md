# Phase 2 平台绑定增强

## 目标

首版网关已经能按 `teamId` 自动建库、上传和检索。第二阶段要把“平台事实库绑定”显式化，减少网关对队伍命名规则的依赖。

## 结论

建议平台后端在后续联调中逐步改为：

- 优先显式传入 `knowledgeBaseId`
- `teamId` 继续作为兼容路由和自动创建兜底
- 平台数据库保存 `teamId -> knowledgeBaseId` 的绑定关系

## 网关职责变化

网关不再依赖队伍名称猜测知识库，而是：

1. 优先使用显式 `knowledgeBaseId`
2. 若未提供，再按 `teamId` 查找
3. 若仍不存在且允许创建，再创建新知识库

## 推荐迁移顺序

1. 平台后端先继续沿用 `teamId`
2. 平台数据库接上后，开始下发 `knowledgeBaseId`
3. 网关保留 `teamId` 兜底，直到平台契约完全稳定
4. 最终平台可只把 `teamId` 用于兼容查询，不再依赖名称匹配
