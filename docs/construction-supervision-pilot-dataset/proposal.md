# 模拟施工监理审查资料包规格提案

## Why

当前项目已经确认以 MaxKB 作为企业级私人知识库与智能体平台主体，第一阶段优先验证：

- 某项目下某施工队伍或分包队伍的开工条件审查
- 某项目下某施工队伍或分包队伍的施工方案审查

在进入源码定制前，需要先构造一套可控、可追溯、接近真实施工业务的模拟项目资料包，用于跑通 Windows + Docker Desktop 本地知识库能力，并为后续 Linux 部署和昇腾模型服务迁移保留稳定契约。

## What Changes

- 定义一个模拟公路工程项目、合同段、监理标段、施工总包和分包作业队伍。
- 定义第一批 10-30 份入库资料的清单、文件类型、metadata 和用途。
- 定义官方公开规范来源的候选清单，优先使用交通运输部公开发布页面或 PDF。
- 定义知识库粒度：项目级逻辑知识库 + metadata 过滤。
- 定义资料生成、入库、检索、审查问答的验收标准。

## Scope

### In Scope

- 模拟项目资料包规格
- 模拟分包作业和审查任务定义
- 资料清单与 metadata 设计
- 规范来源登记与入库策略
- 本地 MaxKB 知识库验证任务

### Out of Scope

- 直接改造 MaxKB 后端数据模型
- 直接构建正式生产知识库
- 直接下载或转载版权不明的规范全文
- 让检索结果直接成为正式审查结论
- 昇腾专属模型部署脚本

## Pilot Name

建议模拟项目名称：

> 南江至东岭高速公路改扩建工程 JD-A1 标段监理审查试点

第一阶段聚焦队伍：

> LJ-01 路基土石方分包作业队

第一阶段聚焦审查：

- 开工条件审查
- 路基填筑施工方案审查

## Expected Outcome

完成后应可以在 MaxKB 中建立一个项目级知识库，上传模拟资料包，完成以下验证：

1. 针对 LJ-01 队伍询问开工条件是否齐备时，可以召回合同依据、监理要求、人员资质、设备清单和报审材料。
2. 针对路基填筑施工方案询问是否合格时，可以召回项目依据、施工方案、质量检评、安全规范和路基施工技术规范。
3. 输出结果必须区分“支持性召回”和“正式审查结论”，人工确认仍是结论入口。
